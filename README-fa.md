# Shah Tunnel 1.3.3 — بستهٔ اجرایی برای GitHub

## ساختار موردنظر مخزن

```text
ShahTunnel/
├── S1T-START.sh
├── install.sh
├── S1T-CHECKSUM.sha256
├── README-fa.md
└── S1T-CAPSULE/
    └── S1T-CORE
```

**داخل `S1T-CAPSULE` فقط `S1T-CORE` قرار می‌گیرد.** این فایل باینری کامپایل‌شده و stripped برای Linux x86_64/amd64 است؛ سورس Go یا ZIP/آرشیو سورس داخل پوشه قرار نمی‌گیرد. فایل checksum و اسکریپت‌های نصب در ریشه‌اند.

## نصب یک‌دستوری

پس از آپلود و Commit فایل‌ها در شاخهٔ `main`، روی هر سرور Ubuntu/Debian با کاربر root اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/shah1dev/ShahTunnel/main/S1T-START.sh)
```

نصب‌کننده باینری را از `S1T-CAPSULE/S1T-CORE` می‌گیرد، checksum را با `S1T-CHECKSUM.sha256` کنترل می‌کند، فایل اجرایی را در `/usr/local/bin/ravanreverse` نصب می‌کند، سرویس systemd را ایجاد/به‌روزرسانی می‌کند، تنظیمات قبلی `/etc/ravanreverse/config.json` را حفظ می‌کند و در پایان منوی `shah-tunnel` را باز می‌کند. فایل دانلودشدهٔ موقت بعد از نصب پاک می‌شود.

## مهم دربارهٔ مخفی بودن سورس

این بسته منبع Go را داخل پوشه یا ZIP قرار نمی‌دهد؛ باینری از سورس متنی قابل مشاهده نیست. با این حال کامپایل، فشرده‌سازی یا رمزگذاری تضمین نمی‌کند که باینری تحت هیچ شرایطی مهندسی معکوس نشود. برای اینکه سورس فعلی دیگر از GitHub عمومی قابل خواندن نباشد، باید `main.go`، `main_test.go` و `S1T-CAPSULE/S1T-SOURCE.tar.gz` و فایل‌های مشابه را از شاخهٔ عمومی حذف کنید. برای پاک‌کردن دسترسی از تاریخچهٔ commit هم تاریخچه باید بازنویسی شود یا مخزن توزیع عمومی جداگانه‌ای بسازید که فقط فایل‌های نصب و باینری را داشته باشد.
