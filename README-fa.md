# شاه تونل (Shah Tunnel) — نسخهٔ 1.3.5

**زبان / Language:** [🇮🇷 فارسی](README-fa.md) · [🇬🇧 English](README.md)

شاه تونل یک **تونل معکوس TCP با احراز هویت** است که اتصال‌های ورودی را از یک سرور عمومی به سرویس TCP روی سرور مقصد منتقل می‌کند. این روش برای زمانی مناسب است که سرویس مقصد نباید مستقیماً روی اینترنت در دسترس باشد یا سرور ورودی مسیر مستقیم مناسبی به مقصد ندارد.

## نحوهٔ کار

```text
کاربر ── TCP ──▶ Hub (ورودی عمومی)
                     ║
                     ║ کانال TLS احراز هویت‌شده
                     ║
                  Agent (خروجی) ── TCP ──▶ سرویس مقصد
```

- **Hub:** روی پورت‌های عمومی تنظیم‌شده گوش می‌دهد و اتصال‌های ورودی را دریافت می‌کند.
- **Agent:** خودش اتصال خروجی احراز هویت‌شده‌ای به Hub برقرار می‌کند و جریان‌های TCP را به مقصدهای تنظیم‌شده می‌فرستد.
- **نگاشت پورت‌ها:** هر پورت عمومی می‌تواند به یک مقصد TCP جداگانه نگاشت شود؛ شناسهٔ نگاشت باید در هر دو سمت یکسان باشد.
- **امنیت ارتباط:** کانال Hub↔Agent از TLS نسخهٔ 1.2 یا بالاتر، بررسی اثرانگشت SHA-256 گواهی Hub و توکن مشترک تصادفی برای احراز هویت استفاده می‌کند.
- **پایداری:** Agent پس از قطع ارتباط تلاش می‌کند دوباره وصل شود؛ systemd می‌تواند سرویس را مدیریت و پس از خطا دوباره اجرا کند.
- **Relay اختیاری:** در چیدمان‌های پشتیبانی‌شده، Relay جریان‌های TCP را به مقصد تنظیم‌شده منتقل می‌کند.

## کاربردها

انتقال اتصال‌های TCP برای پنل‌ها، برنامه‌های وب یا سرویس‌های دیگری که روی یک پورت TCP گوش می‌دهند. برای نمونه، Hub پورت عمومی را می‌پذیرد و Agent آن را به سرویس مقصدی مانند `127.0.0.1:PORT` منتقل می‌کند. مقصد و پورت با توجه به نیاز سرویس تنظیم می‌شوند.

## چه چیزی نیست؟

شاه تونل VPN عمومی مانند WireGuard نیست؛ رابط شبکهٔ مجازی ایجاد نمی‌کند و همهٔ ترافیک IP یک دستگاه یا سرور را مسیریابی نمی‌کند. فقط اتصال‌های TCP تعریف‌شده را منتقل می‌کند. TLS از کانال میان Hub و Agent محافظت می‌کند؛ رمزگذاری لایهٔ برنامه، در صورت نیاز، باید توسط خود سرویس مقصد فراهم شود.

## نصب آسان

روی سرور Ubuntu/Debian با معماری `x86_64`، با کاربر `root` اجرا کنید:

