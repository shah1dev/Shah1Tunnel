## Quick install (short)
Copy & paste the commands below. These assume a Unix-like host with git, bash, tar and coreutils.

```bash
# Clone and enter
git clone https://github.com/shah1dev/Shah1Tunnel.git
cd Shah1Tunnel

# If the embedded archive filename is present as 'null', create a safe symlink so the installer finds it
if [ -f "S1T-CAPSULE/S1T-SOURCE.tar.gz" ]; then
  sudo bash S1T-START.sh
elif [ -f "S1T-CAPSULE/null" ]; then
  ln -sf "$(pwd)/S1T-CAPSULE/null" "$(pwd)/S1T-CAPSULE/S1T-SOURCE.tar.gz"
  sudo bash S1T-START.sh
else
  echo "ERROR: required package archive missing: S1T-CAPSULE/S1T-SOURCE.tar.gz or S1T-CAPSULE/null" >&2
  exit 1
fi
```

# English

## What Shah1Tunnel is (short)
Shah1Tunnel is a small, shell-script-based package manager/installer that restores an embedded source capsule and hands control to the packaged setup scripts. The repository contains an installer (S1T-START.sh), a checksum manifest (S1T-CHECKS.sha256), a Farsi info text (S1T-INFO-FA.txt) and an embedded capsule file under S1T-CAPSULE. Most runtime behavior and protocol implementations live inside the embedded capsule that the installer extracts and executes.

## Confirmed (from repository files)
- Integrity verification: The installer runs `sha256sum --status -c S1T-CHECKS.sha256` and aborts on failure.
- Workspace allocation: The installer searches several writable directories and requires ≥ 16 MiB free; it refuses to run if not found.
- Safe extraction: The archive is unpacked to a temporary workspace and filenames inside the capsule are encoded; the installer decodes them and moves them into place while checking for collisions.
- Cleanup behavior: PACKAGE_CLEANUP controls removal of extracted installer files; the script can remove matching ZIPs in /root that match the embedded manifest.
- Handoff to package: After extraction the script runs the embedded package `setup.sh` (expected at Shah1Tunnel-Core/setup.sh).

## Not confirmed / located in embedded capsule
The following items are likely implemented inside the embedded source capsule and were not available for static inspection from this repository alone; they must be inspected by unpacking the capsule locally:
- Protocols used for tunnels (TCP, UDP, custom multiplexing, obfuscation)
- Encryption and authentication mechanisms (key management, token format)
- Reconnect and keepalive strategies
- Port mapping logic and management interfaces
- Daemon / systemd service files (if generated by the package)
- Architecture-specific binaries or build targets (amd64 / arm64)

## Prerequisites
- bash, tar, base64, sha256sum and basic coreutils
- A writable directory with at least 16 MiB free on one of: $WAT_TMPDIR, /var/tmp, /root/.cache/shah1tun, or /tmp

## How to run (short)
- Ensure the capsule and checksums are present in repository root.
- Run: `sudo bash S1T-START.sh` (or create symlink for S1T-CAPSULE/null to S1T-SOURCE.tar.gz first)
- The installer verifies checksums then extracts the capsule and runs the embedded setup.

## Troubleshooting (short)
- "package files are missing." — missing required files next to S1T-START.sh.
- "package integrity check failed; nothing was executed." — sha256 mismatch; re-download and verify.
- "cannot allocate workspace with at least 16 MiB free" — provide a path with enough free space and set `WAT_TMPDIR=/path`.

## Safety notes
- The installer extracts and executes code from an embedded archive. Review S1T-CHECKS.sha256 and S1T-INFO-FA.txt and run in a controlled environment.
- The installer may remove extracted files and a matching ZIP in /root (only if detected to match the manifest).

## Where to look next (recommended)
1. On a trusted test host, clone the repo and run the quick-install steps above.
2. After sha256 verification passes, let the installer unpack the capsule and inspect the extracted `Shah1Tunnel-Core/` directory (look for setup.sh, install.sh, build scripts and cmd/*).
3. Inspect `Shah1Tunnel-Core/cmd/*` (Go sources) to confirm supported protocols, platforms and encryption choices.
4. If you want the installer to accept the repository's S1T-CAPSULE/null filename automatically, implement a small wrapper in S1T-START.sh that detects the `null` file and uses it as S1T-SOURCE.tar.gz — but do not change checksums without updating S1T-CHECKS.sha256 accordingly.
